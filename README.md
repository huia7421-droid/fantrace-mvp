# NamtanFilm 行程與活動後內容

把 NamtanFilm（Namtan Tipnaree × Film Rachanun）的活動行程，和活動結束後粉絲在各平台發布的內容，整理成一頁。

這是 FANTRACE 的早期試作頁，**只在邀請期間開放**，不對外宣傳。

---

## 這是什麼

頁面分成兩個分頁，最上面可以切換：

- **行程區** — 已公告、還沒發生的活動。日期時間一律換算成台灣時間，並附上官方公告連結與該場的刷推 hashtag
- **內容區** — 活動結束後的飯拍、站姊拍、官方照片、粉絲翻譯。共 **51 筆**，涵蓋 **7 場**已結束的活動

內容可以按**人物**、**內容類型**、**翻譯種類**、**活動**、**拍攝者**篩選。

目前收錄範圍：**2026/09/18 – 2026/11/29**，共 13 場活動。

### 行程卡上的參與者

每張行程卡在標題上方列出這場的參與者，以頭像加名字呈現，讓人一眼看得出是誰的場。
Lunar（NamtanFilm 設計的吉祥物）會用不同顏色標示，和真人區分。

**這些頭像是 FANTRACE 自己畫的示意插畫，不是藝人本人的照片，也不是任何粉絲或官方的素材。**
它們直接內嵌在 `index.html` 裡，不向外部抓圖。

## 這不是什麼

- **不是轉載站。** 粉絲與官方的照片、影片、翻譯，頁面一律只放**連結**，不下載、不重新上傳，所有內容都導回原作者的貼文
- 不是官方帳號，和 GMMTV 或藝人本人無關
- 沒有登入、沒有留言、沒有會員
- 不自動蒐集內容。所有連結都是人工一筆一筆找出來、確認過的公開貼文

## 技術架構

一個檔案，沒有建置流程、沒有框架、沒有依賴。

```
index.html          ← 全部都在這裡（HTML + CSS + JS + 資料 + 頭像）
```

| | |
|---|---|
| 前端 | 單一 HTML，約 61 KB，資料以 JS 常數內嵌 |
| 託管 | GitHub Pages |
| 字型 | Google Fonts（IBM Plex Sans / Mono）— **唯一的外部資源** |
| 圖片 | 三張參與者頭像，以 base64 WebP 內嵌，不發外部請求 |
| 後端 | Google Apps Script（只寫入一份 Google 試算表） |
| 外部函式庫 | 無 |

支援淺色／深色模式（跟隨系統），手機版面為主要設計目標。
頁面標了 `noindex, nofollow`，不會被搜尋引擎收錄。

## 資料結構

兩組陣列，以 `ev` 欄位關聯（一場活動對多筆內容）。

### `EVENTS`

| 欄位 | 說明 |
|---|---|
| `id` | `E01`–`E13` |
| `date` / `time` | **台灣時間**（原始時區在資料整理階段換算；`time` 為空代表時間未公布） |
| `title` | 活動名稱。同一天多場會加「（彩排）」「（正式）」區分 |
| `online` | `true` 線上 / `false` 線下 |
| `venue` | 線下為場地，線上為平台名 |
| `artists` | 陣列，**只放真人**（Namtan / Film / Milk / Love / View / Mim） |
| `tags` | 非真人標籤，例如 Lunar |
| `type` | 直播／代言活動／訪談／見面會／簽售／彩排／接機／衝榜聚會 |
| `cp` | Namtan 與 Film 是否同時出席 |
| `ht` | 該場的刷推 hashtag 陣列。沒有公告 hashtag 時為空 |
| `src` | 官方公告連結。接機、彩排沒有公告，此欄為空 |

### `CONTENTS`

| 欄位 | 說明 |
|---|---|
| `id` | `C01`–`C51` |
| `ev` | 對應 `EVENTS.id` |
| `pf` | 平台 |
| `ct` | 飯拍影片／飯拍照片／站姊拍／官拍／品牌方拍／粉絲翻譯／平台字幕 |
| `fansite` | 是否為粉絲站（站姊）帳號 |
| `who` | 作者帳號 |
| `url` | 原貼文連結（已移除追蹤參數） |
| `date` / `time` | 發布時間（台灣時間） |
| `prec` | `exact` 精確到分／`approx` 原記「左右」／`date_only` 只知日期，`time` 為空 |
| `hrs` | 發布時間距離活動開始幾小時 |
| `subj` | 拍到誰 |
| `tags` | 非真人標籤，例如 Lunar |
| `cap` | 文案裡是否含翻譯 |
| `tr` | 翻譯者帳號 |
| `lang` | 翻譯語言（`zh` / `th` / `en` / `auto`），非翻譯內容為空 |
| `note` | 補充說明，例如「純側拍」「表演環節」「翻譯放在文案」 |

### 三種「翻譯」是不同的東西

| | 怎麼表示 | 性質 |
|---|---|---|
| 完整翻譯 | `ct = 粉絲翻譯` | 人工翻譯整場，多在 bilibili |
| 文案有翻譯 | `cap = true` | 飯拍發布者把對話打在文案裡，片段式 |
| 平台字幕 | `ct = 平台字幕` | 平台自動產生 |

頁面上三者分開標示、可分別篩選，因為它們的即時性和完整度差很多。

## 怎麼更新內容

資料直接寫在 `index.html` 的 `EVENTS` / `CONTENTS` 裡。更新方式：

1. 在本機編輯 `index.html`（**用純文字編輯器，不要用 Word**）
2. 上傳覆蓋到這個 repo
3. 等 1–2 分鐘，GitHub Pages 會自動重新發布

新增活動時，若日期是未來，會自動出現在行程區；過去的活動會從行程區消失，但內容仍保留在內容區。

### 新增參與者頭像

頭像定義在 `index.html` 的 `FACE` 常數裡，值是 base64 的 WebP data URI。
**沒有頭像的人會自動顯示有顏色的字母圈**，不會開天窗，所以不補圖也不影響使用。

## 隱私

頁面會記錄**哪些連結被點了**，用來了解哪一類內容比較有用。每一筆紀錄包含：邀請連結的編號、點了什麼、什麼時候、手機或電腦。

**不會**記錄姓名、email、IP、精確位置，也沒有任何第三方分析服務或廣告追蹤。

紀錄存放在一個獨立 Google 帳號的試算表，權限僅限專案成員，試作結束後刪除。

不想被記錄的話，用不帶編號的網址開啟就可以 —— 內容完全一樣。
